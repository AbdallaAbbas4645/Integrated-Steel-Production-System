# ADR-002 — Atomic server-authoritative workflow commands
**Status:** Proposed for production pending staging integration | **Date:** 2026-10-29

**Context:** Transport, rolling, inventory and dispatch cannot rely on browser-only validation; concurrent dispatches can oversell.

**Decision:** Send discrete commands via `WorkflowService` → adapter → PostgreSQL `factory_stage` RPC, which validates user roles and quantities and serializes inventory-impacting transitions. Separate inventory reads use `factory_inventory`.

**Alternatives:** direct table inserts from browser (easy, weak workflow invariants), custom backend API (more complexity), independent microservices (unnecessary at this scale).

**Consequences:** Stronger transactional integrity but SQL functions become application logic and require schema/RLS integration tests. `SECURITY DEFINER` must be audited. No automatic retry for non-idempotent commands.
